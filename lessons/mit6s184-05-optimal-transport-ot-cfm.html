Chapter 05: Optimal Transport Flow Matching (OT-CFM) & Straight Paths

The Geometry of Generative Paths

In standard diffusion models and basic Continuous Normalizing Flows (CNFs), the trajectories linking the prior distribution (noise) to the target distribution (data) can be highly curved and self-intersecting. This curvature stems from standard independent coupling between the distributions, $q(x_0, x_1) = q(x_0)q(x_1)$. Highly curved paths are computationally expensive to simulate during inference because ODE solvers require many small steps to accurately integrate complex vector fields without massive truncation errors.

Optimal Transport (OT) to the Rescue

Monge-Kantorovich Optimal Transport (OT) provides a mathematical framework for moving one probability distribution to another with minimal effort. The effort is quantified by a cost function, typically the squared Euclidean distance. Minimizing this cost leads to the Wasserstein-2 distance $\mathcal{W}_2$. When we enforce this optimal coupling, particles (data points) travel from noise to data along straight lines without crossing, minimizing the total distance traveled.

Standard Independent Coupling         Optimal Transport Coupling (OT-CFM)
(Curved & Crossing Paths)             (Straight & Non-crossing Paths)
       
x_1 (Data)                            x_1 (Data)
*   *   *                             *   *   * 
 \ / \ /                              |   |   |
  x   x                               |   |   |
 / \ / \                              |   |   |
*   *   *                             *   *   *
x_0 (Noise)                           x_0 (Noise)

Mini-batch Exact OT Coupling

To implement this in practice, we use Mini-batch Optimal Transport. Given a batch of noise samples and data samples, we compute the cost matrix (pairwise distances) and use the Hungarian algorithm (Earth Mover's Distance) to find the optimal assignment.

Tip: Straight paths allow ODE solvers (like Euler or Runge-Kutta) to take much larger step sizes, significantly speeding up the generation process.

Code: Mini-batch OT-CFM Training Step

python

import torch
import scipy.optimize

def compute_ot_coupling(x0, x1):
    """
    Computes optimal transport matching between mini-batch of noise x0 and data x1.
    """
    # Compute pairwise cost matrix (squared L2 distance)
    # Flatten spatial dims if necessary: x0.view(x0.size(0), -1)
    C = torch.cdist(x0.view(x0.size(0), -1), x1.view(x1.size(0), -1), p=2)**2
    # Use SciPy's linear_sum_assignment (Hungarian algorithm)
    row_ind, col_ind = scipy.optimize.linear_sum_assignment(C.cpu().numpy())
    return x0[row_ind], x1[col_ind]

def ot_cfm_loss(model, x1, x0):
    """
    Computes the OT-CFM loss for a batch of data x1 and noise x0.
    """
    # 1. Optimal coupling
    x0_matched, x1_matched = compute_ot_coupling(x0, x1)
    
    # 2. Sample random time t ~ U[0, 1]
    t = torch.rand(x0.shape[0], 1, device=x1.device)
    while len(t.shape) < len(x1.shape):
        t = t.unsqueeze(-1)
        
    # 3. Interpolate (straight paths)
    x_t = (1 - t) * x0_matched + t * x1_matched
    
    # 4. Target velocity
    v_target = x1_matched - x0_matched
    
    # 5. Predict velocity
    v_pred = model(x_t, t.squeeze())
    
    # 6. MSE Loss
    return torch.nn.functional.mse_loss(v_pred, v_target)
